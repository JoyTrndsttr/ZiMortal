# 主动状态挖掘与自适应 rollout

2026-10-08：停止扩充低精度随机标签，新增生产流水线。此文记录实现和运行方式，
**不是“已完成 5k 数据或新模型训练”的报告**。实际数量以运行目录的 `progress.json`
及最终通过审计的 `manifest.json` 为准；当前收益冠军仍为第五轮 huxi。

## 状态来源与优先级

仅从完整合法模拟轨迹提取有多个合法动作的 Observation。轨迹混合冻结 huxi、
当前现金 Q、历史 scale100k 和启发式策略，不采用均匀随机动作来填充数据。
每局保留各重点类别的高分状态，另保留总体分歧最大的状态：

- 吃及完整下比方案；碰／过碰；胡／不胡。
- 红牌、大小牌名堂临界状态，以及剩余牌堆不超过六张的晚局。
- 当前 Q、父策略、启发式动作或动作排名分歧较大的状态。

先用另一个随机流的 32 个共同粒子做搜索筛选。筛选粒子不参与认证与训练标签。
搜索与模型／父策略越不一致、动作收益差相对配对误差越大，精算优先级越高。
筛选均值并列或差值未超过筛选配对误差时，不因argmax选了第一个动作而加分；
筛选误差只用于分配计算，不充当标签认证。
每轮仅增加一个倍增档位，已有粒子不重复计算；调度对昂贵根加预算惩罚，
及时补充候选，避免单个未收敛根长期阻止挖掘。类别配额不足时提高其优先级。

独立训练输入以编码张量和合法动作列表 SHA256 去重。一个牌局可以贡献多个
不同根，但整个 seed 只属于一个 split；seed 尾数9用于验证。默认训练起点2000000，
后续开发评估3000000、正式评估3001000、复盘3002000，与采样范围分离。

## 共同粒子与认证

每粒子从玩家 Observation 独立采样，同一隐藏世界用于所有候选动作。
后续三家都采用冻结 huxi，因此 Q 表示此后续策略及采样分布下的终局净现金收益，
不代表最优 EV。金额目标按100归一化，认证仍用原始结算金额。

新的隐藏世界采样器使用带精确整数权重的动态规划：物理牌分配权重为多项式系数，
先剔除与强制偎提、起手坎、出牌、下比等历史证据冲突的计数，随后逆推起手并重放
**全部**公开历史，只有 Observation 完全一致才接受。不读原局对手暗手或真实牌堆，
不用 MCMC，也不复制或反复使用同一粒子。分布仍是历史一致物理分配条件分布，
**尚未按对手选择动作的概率加权**，不是完成的行为 belief posterior。

粒子数按128、256、512……倍增，默认初始上限1048576。队列耗尽且挖掘预算用完后，
未收敛证据可继续扩展，每根原始 int16 证据最多128MiB；超出限制标为 memory_limited，
不伪造 tie。现金量必须能够无损存入 int16，不裁剪金额。

对每对动作直接计算同粒子的收益差及无偏方差，采用双侧
[Maurer–Pontil empirical Bernstein bound](https://arxiv.org/abs/0907.3740)。
范围由规则推导的未来可结算金额上界给出，包含公开碰偎升级跑提的可能性；
立即胡的收益已知时收紧差值范围。零样本方差仍保留有限样本范围修正项。

默认整个流水线误差预算0.05。第 j 个进入精算的根在采样前固定分配
`alpha_j = 0.05 / (j*(j+1))`，每根再按所有动作对与第 k 次查看的
`1/((k+1)*(k+2))` 分配预算。联合界覆盖自适应查看和从多根择优接受；
不能把普通标准误、bootstrap 成员分歧或一次区间跨零称作收敛认证。

默认 `top_set` 认证最优动作集合：集合内每一对的整个区间都在 ±1 金额单位内，
且每个集合内动作的收益都显著高于每个集合外动作。被淘汰动作之间可以尚未排序；
完整配对区间仍保存。`--scope full_order` 要求所有动作对都完成排序或等价判定。
必须连续两个倍增档位认证相同的最优集合；full_order 还要求整个关系图相同。
“区间包含0”不足以判 tie。并列最优动作使用等质量 policy target，不按噪声打破并列。

该保证依赖规则引擎、收益范围正确以及条件采样独立。它认证冻结策略下的差值，
不能保证真实对手下的收益或神经网络泛化；保守范围也可能使收敛成本很高。

## 数据门槛与自动后续

至少5000个认证训练根，另有至少500个认证验证根。训练集非互斥配额：
吃／比1000，碰／过碰500，胡／不胡200，名堂临界750，晚局1500。
强制动作、筛选粒子、未收敛根、训练 epoch、终局 rollout 数都不算新增根。

达标后才发布 manifest。审计重建每个模型输入、核对文件哈希、认证方法、
根级误差预算、动作关系、split 和配额，并对各 split 抽样重算连续两档的区间。
训练入口再次检查门槛及匹配 manifest 的成功审计，绕开协调器也不能提前训练。

`--train-after` 接着用 `.venv-cuda` 和 RTX5080 训练60 epoch现金Q／policy：
继承冻结 huxi 编码器，训练 bootstrap Q heads，按 policy regret 选择权重。
这是下一代实验候选，编码器仍冻结。随后自动运行独立种子的多对手、轮换座位现金
评估和100局完整重放审查；未经独立收益晋级，不更换冠军。恢复训练需校验原数据、
父模型与 checkpoint，并恢复优化器及随机状态。评估阶段恢复可能重新运行评估。

## 运行、恢复与资源

```bash
scripts/train-active-wsl.sh run --train-after
.venv/bin/python -m zimortal.training.active status
.venv/bin/python -m zimortal.training.active audit
```

默认目录 `data/generated/active-v2`。SQLite WAL 持久化队列、seed cursor、置信预算编号；
NPZ／JSON 原子保存完整档位的粒子证据与区间，断电后重算未保存的半档。
同一运行命令可续跑；代码、环境版本、模型或统计配置改变时必须新建数据版本。
训练只读取每根的紧凑目标，不把原始 rollout 矩阵装入训练集。
证据落盘前保留至少2GiB磁盘余量，不足时明确停止，不占满WSL根分区。

独立 systemd 用户服务使用 CPU torch 生成数据，三个单线程 worker，
MemoryMax=8G、MemorySwapMax=1G、CPUQuota=600%、Nice=10。CUDA用于后续训练，
生成阶段尚未改为 GPU 批量策略推理。日志 `logs/zimortal-active-*.log`，
进度记录 PID 和更新时间；服务错误写 failed，检查实际服务而不能仅凭旧进度称运行中。

规则未定义的模拟分支记录到运行目录 `questions/`，排除整个根，不重采样掉该未来，
不把错误当流局或零收益。问题中的模拟隐藏世界仅供人工规则 review，不进模型输入。

## 实际检查与剩余工作

小预算 smoke 专门检查采样、批量推演、证据落盘、队列恢复与拒绝未收敛根，
禁止 `--train-after`，不发布训练 manifest。实测记录见 [pipeline 检查](active-pilot.json)。
优化 GameState.clone 保持不可变动作／牌组共享，复制全部可变容器；回归对照原
深拷贝逐步状态、四张守恒和终局重放，规则语义不变。

当前尚未达成5k认证数据，也没有本轮训练或棋力提升证据。下一步以生产队列的实际
收敛率和各类别覆盖决定计算投入，完成数据门槛后运行已配置的 CUDA训练、独立收益
评估与规则审查。行为加权 belief、更强后续策略和可证明的真实对手收益仍是能力差距。
