# 连续现金强化学习联赛

用户要求扩大局数，迭代训练，并用更强模型继续打。league-v1从online-rl-v2
开发最佳（第24代）和其匹配的AdamW状态继续；这是实验起点，正式冠军仍为huxi。

## 训练计划

连续四阶段、每阶段12代：第一阶段4096局/代，后三阶段8192局/代，
总计344064局真实训练，50%三人自博弈。初始冻结池包含上一批最佳、huxi、
scale100k、boundary、planning、round3及两个v1模型，再加入最多四个近期快照。
通过检查的阶段候选进入后续池，旧强对手保留。阶段内评估对手固定。
网络沿用20位置1D ResNet，不靠扩大参数量宣称更强；输入只用Observation。
奖励仍为终局净现金/100，不裁剪。学习率3e-5，每代两个epoch、batch512。

```bash
ZIMORTAL_TRAINING_MODULE=zimortal.training.league \
  scripts/train-online-rl-wsl.sh --commit-reports
```

GPU环境.venv-cuda，独立systemd用户服务MemoryMax8G/SwapMax1G/CPUQuota300%/Nice10。
规则和独立完整重放用CPU，批量推理与训练用RTX5080。

## 更换训练基准

阶段内继续累计更新，开发集40独立种子选出候选；每阶段新的400独立种子作为
晋级检查集，不能复用上阶段种子。实验门槛提前冻结：

- 同时聚合所有对手和座位的净现金差，种子聚类bootstrap区间下界大于0。
- 对当前父模型的现金差区间下界大于0。
- 各对手平均收益退步不超过3元/局。

每阶段alpha=0.05/4（98.75%区间）。bootstrap是近似统计方法，不能声称严格
控制全部多重比较；各对手退步约束只看均值，也不等于已证明不退步。
通过者作为下一阶段训练基准，并从其匹配的best_optimizer继续。
未通过者不更换基准，但后续从当前末代权重及optimizer继续，避免反复从旧模型起步。
优化器加载前逐tensor确认它对应初始化权重，学习率按新批配置设置；来源文件哈希冻结。
此流程更换的是实验训练基准，不自动替换网页默认策略或checkpoints/champion.json。

阶段检查数据用于换模后就成为选模数据。全部阶段结束后，锁定实验基准，
仅一次使用1000个新的独立种子与原huxi比较，固定历史对手池含初始实验模型。
这批最终评估不用于选择候选，报告各对手及聚合收益，不能只挑有利对手宣传。

## 种子与恢复

训练每阶段10000000+n*1000000起；开发20000000+n*1000000起；晋级检查
30000000+n*1000000起；最终40000000起。n=0..3，各段均不重叠。
上一批已用9000000段不再称未见测试集。源码、初始权重、配置和换模链冻结。
恢复运行相同命令；逐代恢复last.pt，阶段选择已落盘时跳过已完成阶段。
权重与断点在data/generated/league-v1，报告在docs/training/league-v1，每代及阶段
结果自动commit。league-progress.json指向当前阶段progress.json；服务失败写入
league-error.json并将联赛状态改为failed，不将中断状态描述为仍在运行。

三阶段小规模CUDA验证覆盖256局训练、优化器延续、阶段评估和最终评估；
测试另覆盖接受／拒绝换模及相关种子聚合。小规模验证不作为棋力证据。
距离高强度AI仍缺对强对手稳定的收益增益；继续审查少吃、碰牌拆组和过胡，
最终根据新的评估结果决定后续训练，而非按累计局数判断能力。
