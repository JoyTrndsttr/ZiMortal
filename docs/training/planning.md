# 第七轮：精确 completion distance、现金 EV、rollout 与 belief

## 1. 精确 solver 的口径

`zimortal.analysis.completion` 搜索单人乐观的合法进张路径，区别于替换牌距离或0～3次扰动。自摸、上家摸出、上家打出为代表来源；忽略对手抢牌、提前胡及真实摸牌时间。下家摸牌的胡／碰／跑机会被上家摸牌这一机会超集覆盖，下家打牌的跑机会被上家打牌覆盖。提供仅自摸的来源配置，不能混称两种数值。

从待摸牌状态起，最终胡牌来张算1次进张，听牌=1。当前引擎已经提供合法胡牌时 `analyze_decision` 返回0；必须出牌的阶段先枚举合法出牌，不增加进张计数。当前待处理吃碰、已过胡优先级与免出牌上下文，需要先用真实引擎执行，再求等待状态的距离；不伪造这些上下文。

逐步复用规则引擎执行强制偎／臭偎／提／跑、吃及全部下比、不可拆坎、吃碰后的必要出牌、夹比例外、过张／过碰及15胡门槛。自己的普通摸牌不能凭空留下：只能按引擎合法进张，否则落桌，不能借任意换牌制造短路径。

每次进张消耗一个公开信息下的未知物理副本。未来供牌顺序和来源是乐观假设，不是对真实牌堆的保证；报告未知副本上界与牌堆活张上界（后者不超过剩余牌堆长度）。未来路径不计摸牌时间和中间未接牌损耗，因此不是三人实战中必然完成的步数，也不是动作EV。空牌堆的待摸状态不能再胡。

迭代加深与记忆化判定完整覆盖每个较浅深度；达到物理供牌耗尽仍无路径时才标不可完成。可配置计算预算，`SearchLimit` 明确表示未计算完，**不返回近似数字、不写入向听标签**。远离胡的完整搜索仍可能昂贵。纯终局检查优化避免深度1时展开所有无用的吃牌／出牌分支，近胡实例通常几十毫秒。

输出包含最少进张数、将距离n降至n-1的牌及来源、活张上界、直接胡的胡息、普通名堂、每家付款和赢家净收入。名堂金额使用正式结算函数；未来普通分析不预设天胡／地胡。当前可胡返回的金额明确标注普通金额，并不冒充包括所有历史特殊番的实际结算。

回归实例：fixture 240000030 的14胡结构要2次合法进张；240000032（15胡）、240000008（16胡）只需1次。测试覆盖不可拆坎、供牌耗尽、禁胡状态、空牌堆、预算未完成和当前可胡为0。

网页新增“分析进张距离”，手动请求 `/api/completion`。未完成搜索、需先处理当前来牌与不可完成分别显示，不把未知显示成听牌。求解器仅接收Observation；页面暗手并不送进solver。

## 2. 金额 EV

第五、六轮已将reward改为实际 `payments/100`，保持赢家收两家、输家真实付款、流局0，不使用赢+1／输-0.5，也不截断大牌奖励。本轮value监督为当前soft policy混合的逐动作rollout净收益，再除100用于数值训练。单位为金额而非胜率。

严格说，这是采样隐藏世界与冻结后续策略条件下的Monte Carlo价值，不是最优策略的精确EV，也没有证明已经校准。没有rollout标签的状态只蒸馏旧现金价值头，不能把这些蒸馏目标冒称为真实结算监督。

## 3. Rollout teacher 与隐藏信息隔离

`zimortal.training.rollout.teacher` 输入只有Observation。未知物理牌按公开副本及各家手牌槽位采样，反推初始手牌和牌堆，然后完整重放公开动作，要求所得Observation与输入完全一致。公开DRAW动作本身没有tile；从后续公开响应或当前pending恢复该摸牌，不能读取真实未来牌堆。

重放会拒绝与没偎、强制提、坎不可拆、过碰／过吃、吃和下比、动作优先级矛盾的粒子。廉价的倒序检查先排除强制摸牌证据和拆坎冲突，剩余粒子仍须完整引擎重放验证。采不到合格粒子时报 `SamplingFailure`，没有不一致的fallback。

相同粒子与随机流用于所有候选动作，完整模拟到终局，Q为实际净收益金额平均值，并保存Monte Carlo标准误。`softmax(Q/T)` 中T也以金额计。rollout次数可配置，本轮训练是小规模16次/动作试验，不是已经给十万条状态各做500次搜索。

这种粒子分布是“均匀的、满足公开历史合法性”的后验近似，尚未按对手选择动作的策略概率加权，不能声称已完成校准的Bayesian belief。

独立人工审查 seed31000/dealer1/step34：128次/动作，吃的平均净收益+8.09（标准误2.09），过+32.30（标准误5.91），soft target约8.15%吃、91.85%过。该局不进入训练；两者是固定 `huxi` 后续策略下的估计，不是保证收益或最优Q。

## 4. Belief 与向听辅助头

沿用55×20可见通道与ResNet，不加Transformer。共享latent增加20×5 belief logits，标签为模拟器真实牌堆各牌0～4张，标签不进入特征或采样器；网络按已知物理副本掩码不可能的剩余张数。另加精确进张距离分类头，截断／未知标签跳过，不以扰动次数替代。

对照基线是未知牌在对手手牌槽和牌堆槽之间均匀分配的hypergeometric分布，比较accuracy、NLL及剩余张数MAE，不能仅与永远预测0比较。当前belief网络仍只看到压缩历史通道；完整顺序被rollout粒子重放使用，但尚未进入神经网络序列编码。

## 复现与独立评估

```bash
.venv/bin/python -m zimortal.training.planning build --data data/generated/planning-pilot-v2 --games 200 --roots 32 --rollouts 16
.venv/bin/python -m zimortal.training.planning train --data data/generated/planning-pilot-v2 --epochs 12
.venv/bin/python -m zimortal.training.planning evaluate --report docs/training/planning-comparison.json
```

训练种子33000开始，验证34500开始；额外精确距离题使用2800／2900命名空间×100000，跨训练验证去重复。临胡合成状态只作为距离辅助标签，没有完整可达历史，不作为rollout世界，也不计作新策略决策。评估35000～35049对随机、35500～35549对教师，各150局，按种子聚合三个座位做配对bootstrap。

初次生成使用旧版过慢的分支展开器，中止未保存的临时实验后，用等价终局优化重新生成到v2目录。没有把中止实验计为训练成果，旧模型与已有数据保持可复现。

当前目标差距：完整向听搜索的扩展速度、远离胡的标签覆盖、后验采样接受率、动作Q估计方差、belief校准、真实策略收益均需独立验证。下一步扩大真实模型轨迹的搜索标签，增加中晚局胡息／抢速／赌名堂案例，并按信息集粒子而非真实隐藏状态训练搜索老师。

## 2026-10-08 CPU试验实测

原训练因NPZ加载器OOM被中断，修复后在独立MemoryMax=4GiB服务完成12epoch。不同训练输入11462个，验证2298个；其中真实模型轨迹训练11398个，另64个合成距离辅助题。训练与验证各32/8个rollout根状态、每动作16次；精确距离标签各103/115个，预算未完成不计标签。已有十万级数据仍保留，本轮并未给全部十万条补上搜索标签。

belief采用均匀未知牌分配先验加latent学习残差，零初始化与基线概率一致，并有回归测试。选中的模型验证belief accuracy为56.91%，先验56.53%；NLL为0.8217，先验0.8189，**概率质量尚未优于基线**。距离分类准确率41.74%，现金value对8个验证搜索根状态MAE22.65元；样本不足以证明校准。

独立对随机150局：第五轮18.47元/局，本轮5.90，配对收益差-12.57，按种子聚合95%区间[-18.43,-7.00]，存在明确退步。对教师150局：-6.33与-8.23，差-1.90，区间[-11.33,7.97]，未证明提升。继续使用第五轮收益基线，本轮只标试验。完整逐局与配对结果见planning-comparison.json。

另100局自对局审查完成6295次合法动作、58局胡牌；逐步守恒及完整历史重放通过。这证明抽样对局合法，不能推导策略强或所有规则已正确。

下一步需让rollout根状态跨更多独立开局及阶段分布，增加精确距离标签；当前策略监督数量很小，重复训练12epoch不是扩大标签数据。先解决覆盖与概率校准，再比较搜索蒸馏是否能超过冻结后续策略。

本轮3488次训练终局rollout、992次验证终局rollout，仅覆盖5/2个开局；数量多并不代表根状态多样。后续build已改为按整个种子区间分散选择根状态，原v2数据、结果及校验值保留，不能把新采样方式冒称已经用于本轮。

网页成功路径实测：seed36000/dealer0/试验模型第76步，玩家三可胡六，距离0、22胡、普通1番、每家20元。该普通分析不含天胡／地胡；待处理来牌显示需先执行动作，终局按钮禁用。修复了展示DRAW附带牌值导致分析重放非法的问题，并用整局逐帧测试验证。

GPU复现实验也已完成12epoch，独立权重planning-cuda-resnet.pt，报告planning-cuda-pilot.json。同一数据在5080约16.52秒，Torch版本不同，不能把差异全部归为设备。GPU评估同样未改善收益；保持第五轮基线。GPU结果见planning-cuda-comparison.json及planning-cuda-game-review.json。CUDA安装、资源上限与实际恢复核验见wsl.md。
