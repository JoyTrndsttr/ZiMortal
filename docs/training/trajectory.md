# 成功轨迹规划辅助训练

2026-10-13实现版本`auxiliary_version=trajectory`，在现有ResNet之外增加门子候选
集合编码器。固定候选覆盖全部合法吃牌图案、20种对子／三张／四张同牌；从55×20
可见特征计算局部上下文、持有比例、缺牌和未知副本容量。共享MLP编码、学习池化，
128维残差融合进入原policy/value。它是局部候选集合，不是互斥完整七组计划求解器，
容量估计也不是牌堆概率。未来还须实现完整计划投影与动态可行性验证。

新增预测：最终20种牌的0～4张分布、最终各组的出现次数、12类可叠加名堂、实际
后续取得的牌、是否赢家及胡息。十红系列合并成一个辅助类别，具体番数仍由引擎计算。
后续进张标签是本次轨迹实际取得的牌，包括后来未保留的牌，不是最少缺牌真值。
跑／提与随后胡同一张牌只计一次；空牌堆触发的终局DRAW不计牌。

`training.trajectory`从冻结的最新实验父模型生成完整合法轨迹，保存每个非强制
决策前的Observation编码；逐局四张守恒、普通引擎完整重放和终局序列化核对。
赢家最终settlement.groups给出实际成功分解和名堂，未来信息只作为预测标签。
输家／流局不赋全零成胡路线标签；只参与终局现金、实际后续进张和是否赢家训练。
未知规则整局排除，原始错误记录保留。赢家分解由引擎结算选定，是一条已实现路线，
不是全局最优计划。数据来自模拟模型，不能因为成功就称为人类高质量最优牌谱。

每局总决策权重相同，保留所有玩家、输局和流局，避免只取赢家轨迹。policy用父策略
分布约束漂移，不直接克隆所有成功动作；value学习payments/100。组牌、名堂和胡息
仅监督赢家状态，其他任务监督所有状态。保留获胜轨迹的选择偏差限制：预测描述
冻结行为分布中的实际结果，不等于反事实动作收益或校准最优胡牌概率。

迁移只接受huxi/legacy父模型，原有参数逐项复制，新融合层初始化为零，迁移时
policy/value输出保持一致。新架构独立创建优化器，不冒用旧Adam状态。
检查点保存架构标识、权重、优化器、随机状态及源码／父权重哈希；输入数据NPZ和
每局原始动作证据留本地，不纳入Git。当前入口要求新目录，不支持自动恢复旧目录。

训练／开发以完整牌局划分；开发损失只选辅助模型，最后独立留出现金评估比较父模型、
旧基线和历史对手，轮换座位，按种子聚合。辅助损失下降不代表牌力改善。
首个CUDA冒烟：8训练局、4开发局，217训练决策、78赢家决策，两轮完成，无规则排除。
此项验证数据与梯度路径，不证明能力。新增现金评估入口后的小批生产使用新版本目录。
最终入口CUDA冒烟另完成8训练局、4开发局、178训练决策、51赢家决策与两轮更新；
2个独立种子的现金评估有效，但样本不足以推断强弱。完整测试306通过、1跳过。
曾发现空牌堆终局DRAW没有pending，应保留流局且不生成进张标签，现已回归覆盖。
WSL启动脚本禁写可重建Python字节码，减少紧张磁盘的缓存再生；训练证据和模型不删除。

```bash
ZIMORTAL_TRAINING_MODULE=zimortal.training.trajectory \
  bash scripts/train-online-rl-wsl.sh \
  --directory data/generated/trajectory-v1 \
  --games 128 --dev-games 32 --epochs 8 --holdout-seeds 64
```

每次生产冻结源码与模型，保持原WSL资源上限及2GiB磁盘线。下一步先检查各辅助任务
误差和独立现金收益，再加入互斥完整计划投影、候选方案评分和动态死张重规划。
后续PPO必须保留规划辅助训练／回放，不能仅调用旧PPO就声称新预测头持续获得训练。
